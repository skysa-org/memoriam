# memoriam: instructions for Claude Code

Memoriam is a local-first PWA for learning passages of text by heart. The user types the first
letter of each word while words are progressively hidden. Review is scheduled with FSRS and
practice is rewarded. It is built on the foundations of `../skysa-notes`. Optional sync to Dropbox,
Drive or OneDrive is Phase 2.

Read `docs/ARCHITECTURE.md` before any non-trivial task. It is the source of truth for the
architecture and the decisions behind it. `docs/research.md` is the evidence behind practice and
scheduling. If a task requires departing from either, say so, and propose the edit in the same
change.

## Stack (do not substitute)
- pnpm workspace:
  - `apps/web`: Vite + React + TS, TanStack Router, Dexie, vite-plugin-pwa;
  - `packages/core`: framework-free TS;
  - `apps/api` arrives with sync: Hono on Cloudflare Workers, ported from skysa-notes.
- Validation: zod. Tests: Vitest. Scheduling: ts-fsrs.
- The same ESLint rules and conventions as skysa-notes: functional style, arrow functions, no
  loops, `let` or classes, readonly types, and every user-facing string from `t()`.
- Code ported from skysa-notes keeps its shape; rename `skysa` to `memoriam`. Check the original
  there before reinventing something it already solves.

## Hard rules
- `packages/core` imports nothing from `apps/*`, and has no framework, DOM or Node-only
  dependencies. It must run in the browser, Node and Workers.
- The markdown string is the only source of truth for a passage. Everything else in IndexedDB
  (`cards`, `chunks`) is derived from it, and can be dropped and rebuilt.
- Progress lives in the passage's own frontmatter (`progress:`). Recording a pass rewrites only
  that block, and never `updated`, the body, or keys the app does not know. If the YAML cannot be
  edited safely, refuse and tell the user. Never drop a pass silently.
- `chunker: N` pins the algorithm a passage was split with. Never change an existing chunker
  version's output; add a new version.
- Never lose user data. Import and (later) sync merge progress where they can, and otherwise keep
  both copies.
- `script-src 'self'` with nothing inline, eval'd or `new Function`'d. This is a hard requirement
  (`docs/ARCHITECTURE.md` §9). Nothing may be added to `script-src` in `apps/web/public/_headers`.
- Words the user reads come from the catalog, `t('…')` from `apps/web/src/i18n/t.ts`:
  - whole sentences with `{placeholders}`, and `{ one, other }` for a count;
  - never fragments joined in code.
- Dependencies: MIT, Apache-2.0 or ISC licences only. State why in the pull request.

## Working style
- Work one milestone at a time (`docs/ARCHITECTURE.md` §12). Each one is a pull request with:
  - tests for the new behaviour;
  - an amendment to `docs/ARCHITECTURE.md` if a recorded decision changes;
  - a changeset if anything under `apps/` or `packages/` changes (`pnpm run changeset`, or
    `--empty`).
- Commands: `pnpm dev`, `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm verify`, `pnpm build`.
- `apps/web/src/routeTree.gen.ts` is generated by the router plugin when Vite runs, and committed.
